## 해결하려던 문제

Switch·CCTV·NVR은 장비 종류와 제조사에 따라 상태 조회, 영상 수신, 이벤트 수신 방식이 모두 달랐습니다. 관리자가 장비를 하나씩 따로 확인하지 않고 한 시스템에서 관리하려면, 서로 다른 방식을 하나의 데이터 흐름으로 묶어야 했습니다. 일부 기능은 문서가 없거나 부족했습니다.

## 주요 판단과 선택 이유

- **SDK에 묶인 NVR 연동은 별도 서비스로 뗐습니다.** NVR 제조사 SDK는 C# 환경에 종속돼 있어, 공통 백엔드(Node.js)에 섞지 않고 C# ASP.NET Core 서비스로 분리했습니다. 장비별 차이는 연동부에 가두고, 상태·이벤트는 공통 흐름으로 저장·전달하는 구조입니다.
- **상태는 "바뀐 것"을 이벤트로 남겼습니다.** Switch 상태를 주기적으로 수집하면서 이전 상태와 비교해, 변경이 있을 때만 이벤트로 저장하고 화면에 전달했습니다.
- **문서가 없으면 제조사에 직접 확인했습니다.** 프로토콜·제조사 문서를 먼저 분석하고, 필요한 기능이나 문서가 없을 때 제조사 담당자에게 지원 여부와 API 자료를 요청했습니다.
- **API는 문서로 공유했습니다.** 화면 개발자가 요청·응답 구조를 바로 쓸 수 있도록 Postman 문서를 직접 작성했습니다.

## 구현 과정

1. 관제 대상과 기능을 기준으로 데이터 모델을 설계하고 REST API를 구현했습니다.
2. Switch는 SNMP v2c와 제조사 API로 상태를 수집하고, 변경 이벤트를 MariaDB에 저장한 뒤 WebSocket으로 전달했습니다.
3. CCTV는 RTSP 영상을 FFmpeg로 MPEG1/WebSocket 스트림으로 바꾸고, 부가 기능은 제조사 CGI API로 연동했습니다.
4. NVR은 C# 서비스에서 SDK 콜백 이벤트를 받아 Node.js 백엔드 API로 넘겼습니다.
